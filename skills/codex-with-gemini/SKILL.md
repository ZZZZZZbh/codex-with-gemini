# Codex 与 Gemini 协作

**Codex作为主脑，负责拆解问题、指挥Gemini、自行检索、交叉核验、主笔和最终交付。Gemini的职责限定为：补充检索与查询、全文相关语句修改润色、论文写作审查。**

以下分工贯穿整个任务。用户明确要求理论推导、模型或实验方案分析、数据处理、代码实现时，由Codex在授权范围内承担；Gemini继续按Codex指令承担上述辅助职责。任务名称或稿件中的“研究”“理论”“方法”等词不改变分工。

默认使用简体中文，保留原始文献、公式、代码和必要英文检索词。用户要求实际协作时，应实际调用Gemini并取得与任务对应的回复；查看技能、检查配置或修改本技能属于本地维护，无需发起Gemini对话。

## 职责与范围

| 参与者与职责 | 工作要求 |
| --- | --- |
| Codex主导与执行 | 确定目标、权威材料、授权范围和验收要求；决定Gemini查什么、润色什么、审查什么；自行搜索和分析，核验双方材料，决定采纳内容并完成交付 |
| Gemini补充检索与查询 | 按Codex布置的问题查询文献、事实、术语及表达用法，返回可追溯的原始来源、内容位置和支持的具体表述 |
| Gemini全文相关语句修改润色 | 结合授权文本的上下文，修改用词、语序、语法、衔接、重复和学术表达；提供可采用的改写，保留原意、数据、公式含义及证据强度 |
| Gemini论文写作审查 | 检查论述是否清楚、段落衔接、前后指代、术语与符号表述一致性、主张与引用是否对应，以及结论措辞是否有依据；按原文位置说明问题和必要修改建议 |

- 三项Gemini职责按任务需要选择。全文润色可以返回依据原文逐节修订的完整稿；全文审查须逐节覆盖，长文按章节分批处理并记录实际覆盖范围。
- Codex向Gemini提供所需原文、当前草稿、已有证据和明确问题；让Gemini依据材料审查并独立判断问题，不预设其赞同Codex意见。已有草稿是协作材料，可直接共享。
- Gemini不承担另立研究方案、重构创新点、设计模型或实验、另做理论推导、数据分析、代码实现或脱离原稿另写整篇论文。发现方法、公式、数据或证据的实质疑点时，定位问题并说明依据，由Codex核验和处理。
- Gemini的建议经Codex判断后采用。只读审查交付意见；获授权修改时，Codex才把采纳内容写回指定文件。沿用用户已确定的研究主线、权威版本和编辑尺度。

## Codex指挥检索，双方核验与互补

任务需要资料检索时，Codex和Gemini均实际检索；纯语句修改且无外部资料核验需求时，直接处理语言问题。

1. **明确检索问题**：Codex从任务与原稿中列出需要查证的事实、术语、主张和资料缺口，给Gemini具体问题、范围、关键词方向、来源要求及所需返回内容。对关键主张安排双方检索，补充问题可采用不同关键词、来源或角度，同时关注相反证据与适用条件。
2. **Codex自行搜索**：使用自己的检索工具实际搜索并阅读原始资料，形成自己的判断。仅转述Gemini回复或只打开Gemini给出的链接，不算完成Codex自身检索。可在Gemini生成期间继续自身搜索与核验。
3. **Gemini定向补查**：要求其按布置的问题搜索，返回实际使用的关键词、原始来源链接或DOI、与问题直接相关的短原文或内容位置、该来源支持的表述及适用条件。结合页面可见的检索状态、来源记录和原文锚点核验实际检索情况；仅列出检索式或凭既有知识提供文献时，按待核验线索处理。未实际联网时，按浏览器细则检查和启用可用检索工具，再补齐查询。
4. **对应同一问题核验**：Codex对照双方资料，检查原文、定义、研究条件、时间和证据质量。相同论文或同一原始数据合并为一条来源；不同来源用于补充遗漏、交叉核对。有分歧时回到原始资料查明原因，必要时安排针对性补查并继续自身核验。
5. **形成采用依据**：Codex根据核验后的材料确定可采用的表述、需要修正的主张和待补资料，再用于写作或当前授权任务。按任务复杂度保留简短的来源对应与取舍记录，结论以原始证据为依据。

检索默认以英文检索词和原始英文论文、官方文档、原始数据等一手资料为主。中文法规、标准、本地问题及用户指定的中文材料优先使用相关中文原始资料；核查中文或英文术语、表达用法时，分别对照相应语言的原文。

## 执行、核验与停止

1. **读取材料并布置任务**：核对权威文件、版本、授权范围和交付形式。Codex决定本次需要的Gemini职责，提供具体问题、必要上下文及结果要求；材料较多时保留简短的文件清单。主笔任务尚无草稿时，由Codex组织起草，按需安排Gemini查资料，并在有文本后安排润色或审查。
2. **实际协作并取得结果**：按下文要求在Codex内置浏览器选择模型、提交获授权的材料和任务。确认附件上传及实际读取范围，等待完整回复，核对检索来源、改写语句或审查意见是否覆盖所布置的问题。
3. **Codex核验与处理**：对检索结果执行双方来源核验；对修改建议逐项对照原文、上下文和证据，采纳有依据且在授权范围内的修改。涉及科学含义的疑点由Codex检查定义、公式、量纲、数据或实际实现，再决定处理方式。
4. **补齐并完成**：有漏查、漏读、遗漏语句或尚未解决的具体问题时，Codex安排针对性补充；完成授权范围、关键证据核验和必要修改后交付。按用户时限与实际收益推进，不为重复评价或低收益措辞调整继续交互。同一缺口已无可用线索时，说明具体依赖，完成不受影响的工作。

核验时区分事实、条件下的推导、待验证解释及未知信息。文献、引文、数据和执行记录真实可追溯；搜索摘要、模型意见及双方一致均须回到相应原始证据评估。数值与代码由Codex按风险复算或运行，只报告实际完成的检查。

## 浏览器、模型与思考设置

- **Gemini网页版的登录、上传、提交任务和读取回复，只使用Codex自带的内置浏览器。** 按当前工具文档确认浏览器身份；以`iab`标识时明确选择`iab`。不得自行连接或控制Chrome、Edge等外部浏览器。
- 在当前账号实际模型菜单与必要的Google官方说明中，选择适合本次任务的最强可用模型，并将可见思考设置调至最高可用档位。不固定版本名，也不以提示词中的“深度思考”代替界面设置。
- 正式发送前确认所选状态。页面提供回复详情时，核对实际生成模型及额度或自动路由造成的变化；模型、思考档位和回复属于同一次实际协作记录。
- 最高档因额度、权限或技术问题不可用时，先作合理恢复，再选择实际可用的最高档并说明原因；页面没有独立思考设置时按实际记录。保持完整生成，不为提前结束而点击“立即回答”。
- 浏览器连接、上传、等待及恢复操作见[浏览器操作细则](references/browser-workflow.md)。本技能规定职责与验收要求，具体API与控件以当前工具文档和页面为准。

必要时核对Google官方资料：[模型说明](https://support.google.com/gemini/answer/18648722?hl=en)、[高级推理](https://support.google.com/gemini/answer/16345172?hl=en)、[文件上传](https://support.google.com/gemini/answer/14903178?co=GENIE.Platform%3DDesktop&hl=en)。

## 材料、交付与恢复

- 沿用已获授权发送至Gemini的材料范围；新增敏感资料或目的地缺少授权时按当前工具要求处理。核对版本后上传，以原文短句、公式编号、列名或数值等内容锚点确认实际读取。专用格式按当前支持情况导出必要文本、表格或图像，并保留来源与范围。
- 首先交付用户需要的定稿、修订稿、查询结果或审查意见。需要时附“原文位置或待核问题、Codex检索依据、Gemini补查或修改建议、核验与采纳结果”，无需为简单任务强制新增文件。
- 简要交代Gemini实际承担的工作、模型与思考设置、资料及全文覆盖范围。长任务按需保存Codex工作稿、Gemini原始回复、来源依据和最终稿，分别标明并避免覆盖原始意见。
- Codex对双方意见保持独立判断；保留有依据的不同意见，按证据说明取舍。表达结论先行，使用自然、准确的中文，必要未知与风险集中说明一次。
- 登录失效时由用户在内置浏览器完成认证。浏览器或Gemini阻塞时，保留已完成成果，继续Codex可独立完成的工作，说明未完成的具体环节及恢复条件；错误、拒绝或无实质内容的返回按实际记录。
- 技能及协作记录不保存密码、验证码、API密钥、Cookie、登录凭据或浏览器会话标识。必要记录只保留与任务有关的材料和回复。
