# Codex 与 Gemini 协作

默认流程为：**首轮各自独立出稿；后续基于同一底稿分别修订；每轮都由Codex对比、修改和复核。默认安排两轮，最多三轮，达到停止条件时提前结束。**

Codex负责执行、证据核验和最终交付。默认使用简体中文，保留原始文献、公式、代码和必要英文检索词。审查类任务中的“两版方案”可对应双方各自完整的审查意见；交付深度以用户的问题为准。

## 浏览器范围：仅使用Codex自带浏览器

- **访问Gemini网页版、登录、上传、提交任务和读取回复，只能使用Codex自带的内置浏览器。禁止自行连接或控制用户电脑上的Chrome、Edge及其他外部浏览器。**
- 依据当前工具文档确认内置浏览器身份；工具以`iab`标识时，明确选择`iab`并在该浏览器内获取或新建Gemini标签页。不要仅凭Gemini网址或现有登录状态自动选择其他浏览器，也不复用其他浏览器的标签页句柄。
- 登录认证、标签失效、上传失败或页面超时均在同一内置浏览器内处理。需要用户完成认证时，在该浏览器中展示页面并交接；不因故障自行改用外部浏览器。
- 当前环境没有Codex自带浏览器能力时，明确所缺能力及尚未完成的Gemini步骤，继续可独立完成的分析、核验和交付准备。浏览器操作细节见[浏览器操作细则](references/browser-workflow.md)。

## 通用研究与交付要求

- **目标与范围**：先确定问题、交付物、基线版本、约束和完成标准，并纳入双方共同输入。研究主题、方法模块、工程对象、输出语言及文件格式按任务确定，不固定为某篇论文或某一工程。用户要求沿既有成果修订时，保留指定主线和授权范围，说明实质改动的依据。
- **独立判断**：依据事实、逻辑和相应领域的证据标准评价双方方案，主动指出错误前提、关键缺陷和证据缺口；有依据时提出更可行的替代。对用户或另一模型的赞同与反对都应有具体理由，不为预设结论补造解释。
- **严谨推导**：从可识别的前提、基本原理和可靠数据出发；跨学科借鉴须说明迁移条件。对关键数学表达、数量级和数值独立计算，检查符号、量纲、适用条件、边界和反例。发现矛盾时回到定义、数据及推导修正根因。
- **证据分层**：区分有证据或证明支持的事实与定理、显式条件下的推导、待验证假设及未知信息。文献、引文、数据、案例、接口、执行记录和验证结果须真实可追溯；示例、模拟数据和假设情景明确标注。检索与引用按下文的材料和证据要求执行。
- **执行与验证**：优先利用已有资料和工具，在授权范围内持续完成实际成果；常规判断与修复自主处理，关键歧义、必要认证、缺失事实或授权障碍再请求用户介入。验证聚焦实际风险，区分静态检查、实际运行、通过测试与科学验证，只报告实际完成的检查和结果；失败和不利结果如实纳入裁定。
- **表达与交付**：结论先行，以自然、准确的中文说明结果、依据和必要条件，交付语言与格式遵从任务要求。去除空泛AI表达、重复总结和无信息量的铺陈；必要未知与风险直接说明，同一处不确定性说明一次，避免在正常回答后习惯性追加成串否定式限定。交付前检查遗漏、内部矛盾、无依据主张、引文和格式。

## 按轮迭代的工作流

一轮包含完整的四步：**确定共同输入 → Codex形成并保存本轮方案A → Gemini形成并保存本轮方案B → Codex核验、取舍并形成综合方案S。** 记为第1轮A1、B1、S1，第2轮A2、B2、S2，依此类推。Codex内部的推导、复算和局部修改不另计为一轮。

### 第1轮：独立探索，得到S1

1. 从用户请求确定共同问题、交付要求、数据范围和约束，核对原始材料版本。用户指定的原稿或基线方案属于共同资料。
2. Codex独立检索、分析、推导或计算，完成足以单独阅读和评估的A1，并在向Gemini提交正式方案任务前保存。仅列问题或准备提纲不算完成。复杂任务保存为文件；简单任务可在协作记录中完整保留。
3. 仅通过Codex自带浏览器实际调用Gemini，按下文选择当前可用的最强模型和最高思考等级。提供相同问题、要求、约束及获授权原始资料，要求其自行检索、选择方法并建立完整方案B1。
4. **B1完成前，不发送A1、其摘要、推荐路线、推导结论或反驳意见，也不把任务写成“审查Codex方案”。** 若现有Gemini对话已接触这些内容，在同一登录会话中开启新对话。
5. 等待完整回复，核验附件读取和任务覆盖。若只有零散想法或提纲，围绕原问题补齐，仍不提供A1。保存B1原文、实际模型、思考档位及材料清单后，Codex才比较两版并形成S1。

### 第2轮：围绕关键问题分别改进，得到S2

- Codex从首轮审查中选出最影响结果的2–3个问题，形成双方共用的修订任务：S1、必要的原始材料、已核验的证据、尚存分歧和本轮验收条件。问题较少时按实际数量处理，不凑数。
- 研究任务优先处理创新与既有方法的区别、推导中的关键缺口、现有数据的识别能力、验证设计与主张是否对应。把分歧写成可回答的问题，不要求Gemini认同S1。
- Codex先基于共同输入自行提出A2并保存；然后让Gemini从同一底稿提出B2，**不向Gemini展示本轮A2或其新增结论**。双方都可以推翻S1中的路线，但须说明证据、代价和替代方案。
- 后续版本属于“同一底稿上的分别修订”，不称为彼此完全隔离的独立初稿。允许复用上一轮Gemini对话、附件和已共享底稿；若其提前看过A2，则新开对话并仅传入共同输入。
- A2、B2重点提交实质修改、必要推导、验证调整和修订后的核心方案；未变部分引用上一版，不反复重写全文。Codex核验后形成S2，记录本轮解决、新增和保留的问题。

### 第3轮：按需解决决定性问题，形成最终版本

- 仅在S2仍存在影响选型或可实施性的重大问题、该问题可用现有材料或合理计算解决、且预计收益值得额外一轮时启动。
- 以S2和该问题的证据为共同输入，仍按“Codex先保存A3 → Gemini提出B3 → Codex核验并形成S3”执行。B3完成前不展示A3。
- 聚焦决定性的反例、边界条件、替代路线比较、方法简化或验证落地；避免再次全面发散。若缺少关键观测或无法取得的资料，明确数据依赖并收敛到可行方案，不为同一缺口重复讨论。

### 每轮Codex的对比与裁定

- 使用同一标准评价本轮A、B：问题与约束、事实和文献、推导、数据适配、实施成本、验证力度。对研究任务明确“借鉴的已有内容”和“仍需建立的创新主张”。
- 回到原始证据，独立推导、复算或检验关键反例。两方共同认可的主张也按其重要性核验。
- 逐项说明采用、组合、删除或保留待验的内容及理由，并实际形成综合方案S。综合稿与A、B原稿分开，不覆盖原始意见。
- 保留有依据的备选路线；新版本若增加复杂度而未带来实质收益，恢复更优的旧版本。每轮指出相较上一轮的具体增益。
- 由当前运行的Codex模型承担最终裁定，依据用户目标、证据、数据和资源选择方案；双方一致不是必要的停止条件。

### 轮次、时间与停止条件

- **默认安排两轮，最多三轮，总数包含首次独立出稿。** 首轮已满足交付要求且下一轮预期收益很小时可以提前结束；第3轮须满足上一节的启动条件，不机械用满轮次。
- 每轮各生成一版A和一版B，默认最多三次Gemini实质方案生成。附件读取或遗漏的补齐不另算迭代，但须限于缺失内容；任何改变核心路线或要求重新提出方案的补问都计入下一轮，不通过改名规避上限。
- 第2、3轮合计默认以约20分钟为软时间预算，包含模型等待；首轮读稿、检索和独立出稿按任务规模安排。到达预算后不启动新一轮，收齐正在生成的回复、完成必要核验并交付；不以预算为由降低指定模型或截断回复。用户明确指定时间时按其要求执行。
- 当任务硬约束得到满足、关键事实和推导经相应核验、主要矛盾已处理、方法与验证衔接，剩余变化以措辞或低收益修饰为主时停止。若本轮未带来实质增益，且没有明确可解决的重大问题，也应停止。
- 交付完整可读的最终方案，并简要说明选定版本、实际轮数和停止原因。轮次或预算用尽仍有关键未决项时，说明该问题及其对实施的影响，按证据选出当前最合适的版本。

用户明确要求其他流程时，以用户要求为准。调用本技能即执行实际协作，不只交付提示词，也不重复询问是否调用Gemini。沿用本任务已授权发送至Gemini的材料范围；敏感资料与目的地未获授权时，遵守当前工具的传输确认要求。只读审查不扩大为正文、数据或模型修改。

## 实时选择模型与思考档位

1. 仅在Codex自带浏览器内复用可用的Gemini登录会话，打开实际模型菜单和思考设置；涉及浏览器连接、上传或回复提取时，按需阅读[浏览器操作细则](references/browser-workflow.md)。
2. 根据当前账号菜单及必要的 Google 官方模型说明，选择该任务可用的最高能力模型。优先考虑复杂推理、学术分析能力；不要仅凭版本号、菜单排序或模型自述判断能力，也不要为了省时间而默认使用较低档模型。
3. 将可见的思考等级设置为最高可用档位。模型名称和思考标签均以页面实际显示为准；本技能不固定任何版本名，也不把提示词中的“深度思考”当作已切换设置。
4. 在发送正式问题前确认已选状态；若页面提供回复详情，再核对本轮实际生成模型，检查额度或自动路由是否造成切换。当前模型、思考档位、材料和后续回复应属于同一次实际协作记录，避免用新设置为旧回复背书。
5. 若最高档因额度、账号权限或技术故障暂不可用，先作合理恢复，再选择当前实际可用的最高档，并简要说明实际选项和原因。若页面未提供独立的思考设置，如实记录。

## 材料与回复核验

- 先明确本次问题、交付物和要核对的关键点。提供必要背景、定义、假设、变量、单位、数据范围和原文依据；不要把尚未核实的判断包装成既定事实。
- 给Gemini的首轮独立方案任务应覆盖完整交付要求。例如研究方案需说明问题定义、相关文献、方法、推导、所需数据、验证和失败条件。后续轮次给出共同底稿和具体问题，要求提出可采用的修订内容，避免只返回点评。
- 研究检索默认以英文检索词和原始英文论文、官方文档、原始数据等一手资料为主，核对来源实际支持相应主张。中文法规、标准、术语、本地问题及用户指定的中文材料优先采用直接相关的中文原始资料；来源冲突时比较设计、范围、日期和证据质量。
- 要求 Gemini 对关键主张给出可核验来源；对公式给出必要推导及适用条件；对数据给出所用列、样本范围和计算方法；对文件审查指明页码、章节或其他内容锚点。
- 需要文件时，核对当前版本和范围后上传。文件较多或存在修订版时，保留简短的文件及版本清单；更新后重新提交受影响版本。
- 确认上传完成，再通过原文短句、公式编号、列名、数据行或数值等内容锚点核验附件读取。长文或多文件任务按问题分批处理，并记录实际覆盖范围。
- 对专用工程文件，按 Gemini 当前支持情况选择原文件、导出的表格、图像或文本。使用导出内容时说明其来源与范围。
- 等待可见回复生成完成，读取与本轮问题对应的正文、公式、表格和来源。尚在生成时继续等待；不要为提前结束而切换“立即回答”或截断回复。

## Codex对比审查的证据要求

根据任务风险执行必要核验：

| 内容 | 核验依据 |
| --- | --- |
| 文献与事实 | 打开原始论文、数据或官方页面，检查作者、年份、题名、标识符及其是否支持具体主张 |
| 公式与理论 | 独立推导关键步骤，检查符号、量纲、边界、假设和反例 |
| 数据与数值 | 回到当前文件复算关键数值，核对样本范围、单位、缺失处理和统计定义 |
| 代码与方法 | 结合实际实现、运行或针对关键风险的测试评估建议 |
| 论文审查 | 将意见定位到原文与依据，按用户授权区分审查、建议和实际修改 |

对比表应将“A的主张、B的主张、核验依据、Codex裁定及原因”对应起来。不能以赞同次数或模型能力代替证据，也不把两份方案简单拼接成综合稿。

## 交付与恢复

- 首先交付用户要的完整最终方案，附首轮独立A1、B1及Codex取舍依据；实际进行了后续轮次时，保留对应的共同输入、A、B、S和简短修改记录。复杂任务分别保存；小任务可在同一记录中呈现，无须为轮次强制增加文件。
- 简要交代Gemini实际模型和最高可用思考档位、共同资料范围、每轮关键改进及停止原因。原始方案、分别修订稿、Codex整理和最终综合稿分别标明。
- 较长任务在用户指定位置或当前工作区允许的目录保留必要证据。若原流程已把本轮A发给Gemini，相关答复记为受A影响的复核稿；补做分别出稿时使用新对话，不将旧复核稿改名冒充独立稿或未经影响的修订稿。
- 登录失效时，让用户在浏览器中完成认证，然后继续；不向聊天索取密码，也不在技能文件中保存账号、凭据、Cookie 或会话标识。
- 浏览器或Gemini阻塞时保留已完成的A，继续能独立完成的核验，说明B或比较环节的具体障碍。只有实际读到完整B，才报告“两版独立方案已取得”；错误提示、通用拒绝或无实质内容的返回按实际记录，不计为取得B或完成一轮。
