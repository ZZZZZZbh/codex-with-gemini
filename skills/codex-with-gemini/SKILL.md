# Codex 与 Gemini 协作

Codex 负责当前任务的执行、证据核验和最终交付；Gemini 通过内置浏览器参与独立检索、分析、复核与追问。默认使用简体中文交流，保留原始文献、公式、代码和必要英文检索词。

## 调用后的执行约定

- 用户调用本技能开展研究、搜索或其他需要 Gemini 与 Codex 协作的实际任务时，主动运行 Gemini 协作流程，将实际回复纳入分析。不要只给出供用户复制的提示词，也不要反复询问是否需要调用 Gemini。
- 按当前任务需要发送问题、检索线索、必要摘录和相关文件。沿用用户对该任务明确指定、已授权发送至 Gemini 的材料范围；只提交完成任务所需的内容。若涉及敏感数据且具体数据及目的地尚未得到授权，按当前工具规则在传输前确认。
- Codex 继续完成自己的检索、推导、计算或测试。先形成独立判断再读取 Gemini 结论，尤其适用于公式、研究设计、论文审查和重要结论的复核。协作检索时可以相互补充关键词与来源。
- 研究中出现会改变结论的新材料、重大修订或关键分歧时，再进行有目标的复核。简单排版、措辞调整及已通过且未受影响的检查无需重复提交。
- 用户当前关于指定模型、禁止上传、只读审查、材料保密或任务范围的要求优先适用。

## 实时选择模型与思考档位

1. 复用可用的 Gemini 登录会话，打开实际模型菜单和思考设置；涉及浏览器连接、上传或回复提取时，按需阅读 [浏览器操作细则](references/browser-workflow.md)。
2. 根据当前账号菜单及必要的 Google 官方模型说明，选择该任务可用的最高能力模型。优先考虑复杂推理、学术分析能力；不要仅凭版本号、菜单排序或模型自述判断能力，也不要为了省时间而默认使用较低档模型。
3. 将可见的思考等级设置为最高可用档位。模型名称和思考标签均以页面实际显示为准；本技能不固定任何版本名，也不把提示词中的“深度思考”当作已切换设置。
4. 在发送正式问题前确认已选状态；若页面提供回复详情，再核对本轮实际生成模型，检查额度或自动路由是否造成切换。当前模型、思考档位、材料和后续回复应属于同一次实际协作记录，避免用新设置为旧回复背书。
5. 若最高档因额度、账号权限或技术故障暂不可用，先作合理恢复，再选择当前实际可用的最高档，并简要说明实际选项和原因。若页面未提供独立的思考设置，如实记录。

必要时查阅当前 Google 官方页面并核对发布时间及实际内容：

- [Gemini 模型说明](https://support.google.com/gemini/answer/18648722?hl=en)
- [高级推理功能说明](https://support.google.com/gemini/answer/16345172?hl=en)
- [文件上传与分析](https://support.google.com/gemini/answer/14903178?co=GENIE.Platform%3DDesktop&hl=en)

## 组织材料并获取独立回复

- 先明确本次问题、交付物和要核对的关键点。提供必要背景、定义、假设、变量、单位、数据范围和原文依据；不要把尚未核实的判断包装成既定事实。
- 独立复核时，先提交问题与原始材料，让 Gemini 自行推导或审查；取得首轮回复后，再提供 Codex 的关键分歧进行定向追问。
- 研究检索默认以英文检索词和原始英文论文、官方资料为主。中文法规、标准、术语和本地问题采用直接相关的中文原始资料。
- 要求 Gemini 对关键主张给出可核验来源；对公式给出必要推导及适用条件；对数据给出所用列、样本范围和计算方法；对文件审查指明页码、章节或其他内容锚点。
- 需要文件时，核对当前版本和范围后上传。文件较多或存在修订版时，保留简短的文件及版本清单；更新后重新提交受影响版本。
- 确认上传完成，再通过原文短句、公式编号、列名、数据行或数值等内容锚点核验附件读取。长文或多文件任务按问题分批处理，并记录实际覆盖范围。
- 对专用工程文件，按 Gemini 当前支持情况选择原文件、导出的表格、图像或文本。使用导出内容时说明其来源与范围。
- 等待可见回复生成完成，读取与本轮问题对应的正文、公式、表格和来源。尚在生成时继续等待；不要为提前结束而切换“立即回答”或截断回复。

## 与 Codex 的分析交叉核对

根据任务风险执行必要核验：

| 内容 | 核验依据 |
| --- | --- |
| 文献与事实 | 打开原始论文、数据或官方页面，检查作者、年份、题名、标识符及其是否支持具体主张 |
| 公式与理论 | 独立推导关键步骤，检查符号、量纲、边界、假设和反例 |
| 数据与数值 | 回到当前文件复算关键数值，核对样本范围、单位、缺失处理和统计定义 |
| 代码与方法 | 结合实际实现、运行或针对关键风险的测试评估建议 |
| 论文审查 | 将意见定位到原文与依据，按用户授权区分审查、建议和实际修改 |

对分歧，准确表达双方论点，再按证据裁定；对一致的关键结论，也完成相应核验。保留证据支持较强的判断，明确剩余未知。未经当前任务授权，不把审查扩大成正文改写、数据调整或模型修改。

## 交付与恢复

- 首先交付用户要的研究结果。按任务复杂度简要交代 Gemini 实际模型和思考档位、发送材料范围、关键补充或分歧，以及核验后采用的结论；需要时附可访问的来源和协作证据。无须为小任务强制生成独立报告。
- 较长或需要审计的任务，在用户指定位置或当前工作区允许的临时目录保留必要的输入材料清单、关键回复及核验记录。保存可见原文时标明来源，不将整理后的文字伪装成原始回复。
- 登录失效时，让用户在浏览器中完成认证，然后继续；不向聊天索取密码，也不在技能文件中保存账号、凭据、Cookie 或会话标识。
- 浏览器或 Gemini 阻塞时继续独立工作，同时说明具体障碍与尚未完成的协作环节。只有实际读到回复，才报告已取得 Gemini 意见。

调用示例：

```text
使用 $codex-with-gemini 检索并比较这个研究方向的主要方法，核验关键文献和双方结论。
```

```text
使用 $codex-with-gemini 复核我指定文件中的理论推导，按需上传到 Gemini，给出分歧、证据和修改建议；本次只审查。
```
