# Codex 与 Gemini 协作

[English](README.en.md)

**Codex 作为主脑，负责拆解任务、指挥 Gemini、自行检索、交叉核验、主笔和最终交付。Gemini 的职责限定为补充检索与查询、全文相关语句修改润色、论文写作审查。**

协作通过 Codex 自带的内置浏览器完成。每次提交前确认当前账号适合任务的最强可用模型和最高可见思考档位，取得完整回复后，由 Codex 对照原文及原始证据决定采用内容。

## 职责分工

| 参与者 | 负责内容 |
| --- | --- |
| Codex | 确定目标、权威版本、授权范围和验收要求；布置 Gemini 的具体任务；自行搜索、分析和起草；核验双方结果，完成执行与最终交付 |
| Gemini：补充检索与查询 | 按指定问题补查文献、事实、术语和表达用法，返回可追溯的来源、内容位置及其支持的表述 |
| Gemini：全文相关语句修改润色 | 结合授权文本的上下文，修改用词、语序、语法、衔接和学术表达，保留原意、数据、公式含义及证据强度 |
| Gemini：论文写作审查 | 检查论述、衔接、指代、术语与符号表述、主张与引用的对应关系，并按原文位置给出必要修改建议 |

三项辅助职责按任务需要选择。Codex 可以直接向 Gemini 提供当前草稿、已有证据和明确问题。全文任务按章节记录实际覆盖范围；润色可以返回依据原文逐节修改的完整稿。

理论推导、模型或实验设计、数据处理、代码实现等授权任务由 Codex 承担。Gemini 遇到涉及科学含义的问题时，定位疑点并提供依据，交由 Codex 核验；其职责不扩展为另立研究方案、重构创新点或脱离原稿撰写整篇论文。

## 检索与核验流程

1. **Codex 布置具体问题。** 明确需要查证的事实、术语、主张和资料缺口，给 Gemini 检索范围、关键词方向、来源要求和返回格式。
2. **Codex 自行搜索。** 使用自己的检索工具搜索并阅读原始资料。关键主张由双方检索，补充问题可采用不同关键词、来源或角度；等待 Gemini 时可继续自身工作。
3. **Gemini 定向补查。** 返回实际使用的关键词、原始来源链接或 DOI、短原文或内容位置、支持的表述和适用条件。结合可见检索状态、来源记录和原文锚点确认实际检索情况。
4. **Codex 交叉核验。** 对照同一问题检查原文、定义、条件、时间及证据质量。同一论文或原始数据合并为一条来源；分歧回到原始资料查明，必要时安排针对性补查。
5. **Codex 取舍并交付。** 将核验后的证据用于当前授权任务，审查 Gemini 的修改建议并完成定稿、修订或意见交付。

如果 Gemini 的普通回复仅提供既有知识、检索式，或明确说明未联网，Codex 应检查页面的工具和来源选项，按可用能力启用搜索或 Deep Research，再补齐查询。使用 Deep Research 时，先核对计划只覆盖所布置的资料查证问题，再启动并等待完整结果。检索完成需有可核验结果，并由 Codex 打开关键原始来源复核。

检索以原始英文论文、官方文档、原始数据等一手资料为主。中文法规、标准、本地问题和指定中文材料优先使用直接相关的中文原始资料；专业术语和表达分别对照相应语言的原文。纯语句修改且无外部资料核验需求时，直接处理语言问题。

## 润色、审查与停止条件

- 核对权威文件、版本和授权范围；长文按章节处理并记录已覆盖内容。
- Gemini 根据原文提出可采用的改写和审查意见，Codex 逐项核对含义、上下文和证据强度。
- 只读审查交付意见；获得修改授权后，由 Codex 将采纳内容写回指定文件。
- 对漏查、漏读、遗漏语句及具体分歧安排针对性补充。完成授权范围、关键证据核验和必要修改后交付，按用户时限和实际收益决定后续交互。

## 运行条件

当前 Codex 会话需要具备内置浏览器 UI 操作能力，并能访问 Gemini 网页。上传功能还需要宿主提供文件选择器接口。Gemini 账号的订阅、剩余额度及实际菜单决定可用模型、检索工具与思考档位。

Gemini 的登录、上传、提交和回复读取均在 Codex 自带浏览器中完成；工具以 `iab` 标识该浏览器时，明确选择 `iab`。认证或页面故障也在同一内置浏览器内处理；若该能力不可用，保留已完成成果并说明尚缺的协作步骤。

模型选择依据当前菜单、能力说明及必要的 Google 官方资料，不固定模型版本。每次发送前检查选中状态；页面提供回复详情时，进一步核对实际生成模型及额度或自动路由造成的变化。思考设置使用可见的最高可用档位，等待完整生成。

浏览器控制能力由宿主环境提供；本仓库提供技能指令、界面元数据和操作细则。用户在 Codex 自带浏览器中登录自己的 Gemini 账号。

## 安装

推荐在 Codex 中使用内置的技能安装器：

```text
使用 $skill-installer，从 https://github.com/ZZZZZZbh/codex-with-gemini
安装 skills/codex-with-gemini。
```

也可以下载或克隆仓库，将 `skills/codex-with-gemini` 整个文件夹复制到当前客户端实际读取的个人技能目录。保留一个同名安装位置，安装后在技能列表中确认 `codex-with-gemini`，按客户端要求刷新或重新启动。

更新已有安装时，同步技能主体、`agents/openai.yaml` 和 `references/browser-workflow.md`，确保入口描述、默认提示和执行细则采用同一分工。

## 本地验证方法

使用无敏感信息的合成论文段落，加入可核验的事实错误、夸大结论和语言问题，并为各句编号。例如，以 NSE 和 KGE 评价指标为主题，让 Codex 布置定义与基准值查询、逐句润色和写作审查任务。

验证应覆盖以下实际行为：

1. Codex 明确 Gemini 的具体问题与职责，同时用自己的检索工具搜索并阅读原始资料。
2. 检查 Gemini 的模型及思考设置，观察实际检索状态，取得完整来源结果；普通回复未联网时，核验启用可用搜索工具后的补查结果。
3. 检查每句是否被审查、改写是否保留原意，科学疑点是否留给 Codex 核验。
4. Codex 打开关键来源，核对定义、公式、页码和适用条件，合并重复来源，记录采纳或修正建议的理由。
5. 对比原稿和最终稿，确认改动覆盖授权范围，且 Gemini 的工作维持在三项辅助职责内。

需要测试附件能力时，可生成包含随机标识与原文的 TXT 文件，通过实际上传和内容锚点验证读取；正文任务和附件读取分别记录结果。运行记录保存在使用者自己的工作目录中。

## 文件与登录信息

上传以当前任务指定或明确授权的材料为范围。技能仓库保存可复用的指令和项目说明；研究原稿、测试记录、截图、私人对话链接及浏览器状态保存在使用者自己的工作目录中。账号密码、验证码、API Key、Cookie 和登录令牌不写入技能或协作记录。

提交 issue 或 PR 时，检查内容是否含有个人信息或私有材料。登录失效时由用户在内置浏览器完成认证，恢复后继续。
