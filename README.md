# Codex 与 Gemini 协作

[English](README.en.md)

让 Codex 通过内置浏览器与 Gemini 协作，完成研究、检索、推导、方案设计、论文审查及数据或代码分析。首轮双方独立出稿，后续基于共同底稿分别修订；每轮由 Codex 核验证据、取舍并形成综合方案，负责最终交付。

默认安排两轮，最多三轮，包含首次独立出稿；达到停止条件时提前结束。每轮发送前确认 Gemini 当前最强可用模型和最高思考档位，按任务需要提交已授权的材料，取得完整回复后与 Codex 的方案及原始证据交叉核对。

## 功能

- 首轮先保存 Codex 完整方案，再让 Gemini 根据同一问题与原始材料独立作答。
- 后续双方根据同一综合底稿和关键问题分别修订；Gemini 作答前不接触 Codex 本轮方案或新增结论。
- 实时检查模型菜单与思考等级，每轮确认最高可用档位，不固定某个模型版本。
- 按任务范围上传相关文件和数据，分别核对上传状态、内容读取和实际覆盖范围。
- 获取完整回复，围绕关键问题开展有上限的修订，并按实质收益及时停止。
- 对照 Codex 的独立检索、推导、计算和测试，按证据处理双方分歧。
- 分别保留双方方案、综合稿、材料版本和核验依据，使每轮修改可追溯。
- 登录失效时交由用户在浏览器完成认证，恢复后继续工作。

## 运行条件

当前 Codex 会话需要具备内置浏览器 UI 操作能力，并能访问 Gemini 网页。上传功能还需要宿主提供文件选择器接口。Gemini 账号的订阅、剩余额度及实际菜单决定可用模型与思考档位。

Gemini 的登录、上传、提交和回复读取均在 Codex 自带浏览器中完成；工具以 `iab` 标识该浏览器时，明确选择 `iab`。技能禁止自行连接或控制本机 Chrome、Edge 等外部浏览器。认证或页面故障也在同一内置浏览器内处理；若该能力不可用，保留已完成的分析，说明尚缺的协作步骤。

浏览器控制能力由宿主环境提供；本仓库提供技能指令、界面元数据和操作细则。用户在 Codex 自带浏览器中登录自己的 Gemini 账号。

## 协作流程

一轮记为“共同输入 → Codex 方案 A → Gemini 方案 B → Codex 综合稿 S”。Codex 先保存本轮 A，取得完整 B 后再比较与核验，综合稿与双方原稿分别保留。

1. **首轮独立出稿**：明确问题、交付要求、材料版本和约束，保存完整 A1。让 Gemini 根据同一问题和授权原始资料形成 B1；在 B1 完成前不发送 A1、其摘要或推荐路线。核验后形成 S1。
2. **第二轮分别修订**：从首轮选出最影响结果的 2–3 个问题，以 S1、必要原始资料、已核验证据和验收条件作为共同输入。Codex 先保存 A2，Gemini 再形成 B2，随后由 Codex 核验并形成 S2。
3. **按需第三轮**：只有仍存在影响选型或实施的重大问题、可用现有材料或合理计算解决且值得额外一轮时，才以同样方式形成 A3、B3 和 S3。
4. **证据裁定与交付**：将双方主张、核验依据和取舍理由对应起来，实际完成综合方案。交付完整最终版本，并说明模型与思考设置、材料范围、每轮实质改进、实际轮数和停止原因。

后续轮次中，Gemini 只接收共同底稿与任务资料，在完成本轮 B 前不接触本轮 A 或新增结论。若已接触，需在同一内置浏览器中新建对话，重新提供共同输入。后续版本按“共同底稿上的分别修订”记录。

默认两轮、最多三轮，总数包含首轮；首轮已满足要求且继续修订收益很小时可以停止。改变核心路线或要求重新提出方案的追问计入下一轮，补齐附件读取或遗漏内容限于缺失部分。第 2、3 轮合计默认以约 20 分钟为软预算，包含模型等待；到时收齐正在生成的回复并完成必要核验，不再启动新一轮。用户指定的流程和时间优先适用。

模型设置以网页选中状态为依据；网页提供回复详情时，进一步检查本轮实际生成模型。额度或权限发生变化时，说明实际采用的配置。

## 本地验证方法

可让 Codex 创建两份合成 TXT 文件：一份包含随机测试标识与问题，另一份包含数据和另一个随机标识。先在本地保存参考结果，再上传文件，请 Gemini 返回标识、结果和必要推导。

一个可复现的数据案例是：时间为 `0、2、5、9、10 s`，功率为 `0、12、6、4、0 W`，相邻点之间按线性变化处理。参考结果为逐段能量 `12、27、20、2 J`，总能量 `61 J`，时间平均功率 `6.1 W`，样本算术平均值 `4.4 W`。

检查附件标识与数据是否准确、回复是否完整、数值与单位是否一致，并核对首轮 A1 在提交 Gemini 前已保存、Gemini 输入未包含 A1。这个简单计算可在满足停止条件后结束首轮。

测试后续修订时，选用存在实质待解问题的任务，检查双方是否接收同一底稿、A2 是否先于 B2 保存、B2 是否未接触 A2，以及综合稿是否给出核验依据、改进内容和停止理由。实际轮数应符合默认两轮、最多三轮及提前停止条件。

保留当前环境下的实际结果。仓库发布内容采用通用技能与说明文件，本地运行记录由使用者保存。
